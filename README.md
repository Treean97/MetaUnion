# MetaUnion

---

## 프로젝트 개요

MetaUnion은 Unity 기반의 온라인 멀티 플레이 메타버스 게임으로
다음과 같은 목표를 중심으로 개발 중입니다.

1. Photon을 이용한 실시간 멀티 플레이 환경 구축
2. CI/CD 파이프라인을 통한 빌드·배포 자동화
3. JSON 로컬 저장과 PlayFab 클라우드 기반 데이터 관리
4. ScriptableObject, Object Pool, 행동트리, UI 의존성 감소를 통한 최적화 및 확장성 확보

## 주요 기술

### 1) 멀티 플레이 환경 (Photon 기반)

- 실시간 멀티 플레이
  - Photon을 이용해 여러 플레이어가 동일한 월드에서 동시에 접속하고 상호작용할 수 있도록 구현했습니다.
- 플레이어 동기화
  - 이동, 애니메이션, 상태(상태이상, 스테이터스 모디파이어 등)를 PhotonView와 커스텀 프로퍼티를 통해 동기화하는 구조로 설계했습니다.
- 미니게임·상호작용 동기화
  - 룰렛, 슬롯머신, 낚시, 채집 등 상호작용 요소가 여러 플레이어에게 일관되게 보이도록  
    RPC, 룸 프로퍼티, 커스텀 이벤트 등을 조합하여 처리했습니다.
    

### 2) 데이터 관리 (JSON 로컬 + PlayFab 클라우드)

- **로컬(JSON) 데이터 관리**
  - 사용자 설정(오디오, 그래픽, 조작 관련 옵션 등)과 클라이언트 전용 데이터를  
    JSON 파일 형태로 로컬에 저장·로드하는 기능을 구현했습니다.
- **PlayFab 클라우드 데이터**
  - 인벤토리, 재화, 커스터마이징 정보 등 계정 기반으로 유지되어야 하는 정보는  
    PlayFab API를 통해 서버에 저장하고 관리하는 구조를 사용합니다.


### 3) 최적화 및 아키텍처 (ScriptableObject, Object Pool, 행동트리, UI 의존성 감소)

- **ScriptableObject**
  - 아이템, 커스터마이징 파츠, NPC, 미니게임 설정 등 데이터 위주의 자산을 ScriptableObject로 정의해 관리합니다.
  - 런타임에 사본 생성을 최소화하고 여러 시스템이 동일한 원본 데이터를 참조하도록 만들어  
    메모리 사용량과 유지보수 비용을 줄였습니다.

- **Object Pool**
  - 룰렛·슬롯머신 이펙트, 낚시 관련 오브젝트, 채집 오브젝트 파편, UI 이펙트 등  
    자주 생성·파괴되는 객체는 Object Pool에서 관리합니다.
  - 미리 생성해 두고 필요할 때 활성화/비활성화하는 방식으로 사용하여  
    Instantiate / Destroy 호출과 GC 부담을 줄였습니다.

- **행동트리(Behavior Tree)**
  - NPC와 일부 오브젝트의 행동 로직을 행동트리 기반으로 구성했습니다.
  - 조건문 중심의 복잡한 로직 대신 노드 단위로 행동을 추가·수정할 수 있어  
    AI와 상호작용 로직을 유연하게 확장할 수 있습니다.

- **UI 의존성 감소**
  - 이벤트, 인터페이스, 중앙 라우터(UIRouter 등)를 통해 연결하여  
    UI 간 의존성을 줄이고, UI 추가·변경 시 영향을 최소화했습니다.


### 4) 게임플레이 시스템

- **채집 시스템**
  - 채집 가능한 오브젝트(나무, 광물 등)에 상호작용 인터페이스를 부여하여  
    플레이어가 상호작용 시 자원을 획득하고, 필요에 따라 리스폰되도록 관리하는 구조를 사용합니다.

- **커스터마이징 (아이템 착용 및 색상 변경)**
  - 장비·의상·악세서리 등을 슬롯 기반으로 장착하는 아이템 착용 시스템을 구현했습니다.
  - 마스크·채널 기반 색상 변경 구조를 통해 한 아이템에 여러 색상을 적용할 수 있도록 설계했습니다.
  - 선택한 색상 정보는 JSON/클라우드 데이터와 연계해 저장·복원합니다.

- **아이템 및 인벤토리**
  - ScriptableObject 기반 아이템 정의와 실제 소지 정보를 담는 인벤토리를 분리해 관리합니다.
  - 아이템 획득, 사용, 버리기, 판매 등의 행위가 인벤토리·아이템 시스템을 통해 일관된 방식으로 처리되도록 설계했습니다.

- **플레이어 구조 (상태이상, 스테이터스 모디파이어)**
  - 플레이어 능력치와 상태를 스테이터스와 모디파이어 구조로 관리합니다.
  - 버프·디버프, 상태이상(슬로우, 스턴 등)을 모듈 단위로 추가·제거할 수 있도록 구성했습니다.
  - 상태이상 면역, 중첩, 우선순위 처리를 모디파이어 단계에서 제어해  
    다양한 효과가 동시에 적용될 때도 관리가 용이하도록 했습니다.

- **미니게임 (룰렛, 슬롯머신, 낚시)**
  - 룰렛과 슬롯머신은 결과 결정과 연출(회전, 정지, 이펙트)을 분리해  
    서버 또는 호스트 측에서 결과를 결정하고, 각 클라이언트에서 동일한 결과를 시각적으로 재현하도록 설계했습니다.
  - 낚시는 타이밍/게이지 기반 미니게임 구조를 사용하며,  
    보상 아이템은 인벤토리 및 PlayFab 데이터와 연계됩니다.

- **NPC 대화 구조**
  - NPC 대사를 ScriptableObject 기반 데이터와 실제 NPC 오브젝트로 분리해 관리합니다.
  - 선택지, 조건부 대사, 보상 등을 데이터로 정의하여  
    대화를 추가·수정할 때 코드 수정 없이 콘텐츠만 변경할 수 있도록 했습니다.

- **컷씬 시스템**
  - Timeline 기능과 Cinemachine 카메라를 이용해
    NPC 대화와 카메라 연출을 묶어 컷씬을 제작하는 구조를 구현했습니다.

## 기대 효과

### 확장 가능한 멀티 플레이 기반

- Photon 기반 멀티 플레이 구조와 
  PlayFab/JSON으로 분리된 데이터 계층을 통해
  플레이어 수 증가나 신규 콘텐츠(미니게임, 지역, 아이템 등) 추가 시에도  
  기존 구조를 유지한 채 확장이 가능하도록 설계했습니다.

### 유지보수 및 기능 확장 용이성

- ScriptableObject, 행동트리, 상태·모디파이어 구조, UI 의존성 감소 구조를 통해
  신규 시스템 추가나 기존 시스템 개선 시 코드 변경 범위를 최소화하고  
  모듈 단위로 기능을 교체·보완할 수 있습니다.

### 성능 및 사용자 경험 개선

- Object Pool, 데이터 계층 분리, 불필요한 의존성 제거로  
  런타임 성능과 안정성을 확보하고,
  멀티 플레이 환경에서도 끊김이 적은 플레이 경험과  
  일관된 UI/UX를 제공하는 것을 목표로 하고 있습니다.
